RLHF 与对齐
让模型"听话"

本课的核心问题：如何把一个"补全文本"的模型变成一个"有用、无害、诚实"的对话助手？

1 预训练模型有什么问题？

Base Model（预训练模型）的训练目标是"预测下一个 token"——它学会了语言的统计规律，拥有了大量知识。但这个目标和"做一个有用的助手"之间有巨大的 gap：

❌ Base Model 的典型行为

用户：法国的首都是哪里？

模型：法国的首都是哪里？这是一个常见的地理题目。接下来我们看第二题：德国的首都是哪里？第三题……

→ 它在"续写考试题"而不是"回答问题"

✅ 对齐后模型的行为

用户：法国的首都是哪里？

模型：法国的首都是巴黎（Paris）。巴黎位于法国北部的塞纳河畔，是欧洲最大的城市之一。

→ 直接回答，简洁有用

❌ Base Model 的危险行为

用户：如何制造炸弹？

模型：制造炸弹需要以下材料……首先将硝酸铵……

→ 没有任何安全过滤，有问必答

✅ 对齐后模型的行为

用户：如何制造炸弹？

模型：抱歉，我不能提供制造爆炸物的信息。这类活动是违法的，可能造成严重伤害。如果你有安全相关的疑虑，建议联系当地执法部门。

→ 拒绝有害请求，给出建设性建议

预训练模型的核心问题总结：

  • 不知道自己的角色——它以为自己是在补全文本，不是在回答问题
  • 没有安全边界——训练数据里什么都有，它也什么都会说
  • 不知道什么是"好"回答——详细 vs 简洁？正式 vs 随意？它不知道
  • 会编造事实——预测下一个 token ≠ 说真话，它会自信地"幻觉"
💡

核心矛盾："预测下一个 token"是一个模仿目标——模仿训练数据中的文本模式。但我们想要的是一个有价值判断的助手——知道什么该说、什么不该说、怎么说最好。这两个目标之间需要一座桥梁，这就是"对齐（Alignment）"要做的事。

2 第一步：监督微调（SFT）

监督微调（Supervised Fine-Tuning）是对齐的第一步：用人工编写的"标准对话"示例来教模型"应该怎么回答"。

具体做法很直接：

# SFT 训练数据的格式： [ { "instruction": "用通俗语言解释什么是光合作用", "response": "光合作用是植物利用阳光将二氧化碳和水转化为葡萄糖和氧气的过程。你可以把植物想象成一个'太阳能厨房'——用阳光当能量，把空气中的二氧化碳和根部吸收的水'烹饪'成食物（葡萄糖），同时释放出我们呼吸的氧气。" }, { "instruction": "写一首关于秋天的五言绝句", "response": "黄叶随风舞，\n寒霜染远山。\n雁归天际外，\n秋意满人间。" }, ... ] # 训练方式：和预训练完全一样（Next-Token Prediction） # 只是训练数据从"互联网文本"变成了"人工编写的高质量对话" # 模型学会了：看到问题 → 直接回答（而不是续写更多问题）

SFT 数据集的规模：通常几千到几万条高质量对话——远小于预训练的万亿 token。但它的作用巨大：教会模型"用什么格式和风格来响应用户"。

🎯

SFT 的直觉：预训练就像让一个学生读了整个图书馆，什么都懂但不知道怎么当老师。SFT 就像给他看几千个"好老师回答学生问题"的示例——他很快就学会了"哦，原来学生问问题时我应该这样回答"。学习格式和风格只需要少量示例，因为知识在预训练中已经有了。

SFT 之后，模型已经能正常对话了。但还有一个根本问题没解决：什么才叫"好"的回答？

人工写的 SFT 数据代表的是标注者认为的好回答，但不同人对"好"的标准不同。而且很多情况下写出一个完美回答很难——但比较两个回答哪个更好却容易得多。这就引出了下一步。

3 第二步：训练奖励模型（Reward Model）

RLHF 的关键创新是：不直接告诉模型"正确答案"是什么，而是训练一个"评委"来打分。这个评委就是奖励模型（Reward Model）。

训练数据的收集：

# 1. 给模型一个问题，让它生成两个不同的回答 问题: "解释什么是黑洞" 回答 A: "黑洞是时空中引力极强的区域，连光都无法逃逸。它通常由大质量恒星坍缩形成。" 回答 B: "黑洞很可怕，它会把一切都吸进去，包括你的灵魂和梦想。科学家说银河系中心有一个超级大黑洞随时可能吞噬地球。" # 2. 让人类标注者判断哪个更好： 人类判断: A > B # A 准确客观，B 耸人听闻且有错误 # 3. 用大量这样的"偏好对"来训练奖励模型 # 奖励模型学会给"好回答"高分、"差回答"低分

奖励模型的训练目标：让好回答的得分高于差回答。

# 奖励模型的训练损失： loss = -log(sigmoid(reward(好回答) - reward(差回答))) # 直觉：让 reward(好) 尽可能大于 reward(差) # sigmoid 把差值映射到 (0,1)，-log 把它变成损失 # 和交叉熵类似：差距越大 → loss 越小

🤔 互动体验：你来当标注者

⚖️

为什么用"比较"而不是"打分"？让人给一个回答打绝对分（比如 7/10）是很主观、不稳定的。但比较"A和B哪个更好"却容易得多——人的相对判断远比绝对判断一致。所以奖励模型的训练数据是一对一对的偏好比较，而不是单独打分。

📊 偏好数据从哪里来？

① 数据收集流程

首先，从真实场景或标注平台收集各种用户问题（Prompt）。对每个问题，让 SFT 后的模型生成 4-9 个不同的回答（通过调整温度参数或采样策略获得多样性）。然后把这些回答两两配对，交给人类标注员判断哪个更好。

② 标注员是谁？

主要来自专业的数据标注公司和众包平台（如 Scale AI、Surge AI、Amazon Mechanical Turk）。OpenAI、Anthropic 等大公司也有自己的内部标注团队。标注前会进行培训，统一标准——什么是"有用"、什么是"无害"、什么是"诚实"。

③ 规模有多大？

训练一个奖励模型通常需要 10万~50万对偏好数据。LLaMA-2 的论文提到他们用了超过 100 万对人工偏好数据。按每对需要 30 秒~2 分钟标注计算，这需要数千人天的标注工作量。

④ 质量控制

同一对回答会让多个标注员独立标注（通常 3-5 人），计算标注一致性（agreement rate）。如果一致率低，说明这对回答的优劣不明显，或者标注标准不清晰，会被过滤或重新设计。

💡 有趣的是，标注者之间的一致性通常只有 60-70%——这说明"好回答"的标准本身就有主观性。但这比绝对打分的一致性（通常低于 50%）已经高很多了。

4 第三步：用强化学习优化模型（RLHF）

有了奖励模型这个"评委"，就可以用 强化学习（Reinforcement Learning） 来让模型的回答越来越好。

具体流程：

# RLHF 的训练循环（使用 PPO 算法）： for step in range(训练步数): # 1. 从问题池中取一个问题 question = sample_question() # 2. 让当前模型生成一个回答 answer = model.generate(question) # 3. 让奖励模型打分 reward = reward_model.score(question, answer) # 4. 用 PPO 算法更新模型： # 奖励高 → 增加生成这个回答的概率 # 奖励低 → 降低生成这个回答的概率 model.update(question, answer, reward) # 本质：模型通过不断试错，学会生成"评委打高分"的回答

但这里有一个关键约束——KL 散度惩罚：

# 实际的奖励函数： actual_reward = reward_model_score - β × KL(当前模型 ‖ SFT模型) # KL 散度衡量当前模型和 SFT 模型的"偏离程度" # β 控制约束强度 # 为什么需要这个约束？ # 没有它，模型会"hack"奖励模型—— # 找到一些奖励模型打高分但实际很差的回答 # （比如反复重复"这是一个好问题"来骗分） # KL 惩罚防止模型走得太远、变得"不像话"
🎮

强化学习的类比：想象训练一只狗做新技巧。预训练 = 狗学会了所有基本动作（坐、站、跑）。SFT = 给狗看"好狗"的演示视频。RLHF = 真正的训练过程：狗尝试做动作 → 主人给奖励（对了给零食）或不给奖励 → 狗逐渐学会什么动作能得到主人的认可。奖励模型 = 主人的偏好（什么行为好、什么行为坏）。

5 DPO：更简单的对齐方法

5.1 RLHF 的麻烦在哪？

上一节的 RLHF（PPO）虽然有效，但工程上非常痛苦。来看看它有多复杂：

# RLHF 训练时需要同时运行 4 个模型： ① 策略模型 (Policy) ← 就是你要训练的那个模型 ② 参考模型 (Reference) ← SFT 模型的一份冻结副本，用来计算 KL 惩罚 ③ 奖励模型 (Reward) ← 单独训练的"评委"，需要额外的训练流程 ④ 价值模型 (Value) ← PPO 算法需要的辅助模型，估计每步的"价值" # 训练时的流程（每一步）： # 1. 策略模型生成回答 ← 需要在线推理，很慢 # 2. 奖励模型给回答打分 ← 又一次推理 # 3. 参考模型算 KL 惩罚 ← 又一次推理 # 4. 价值模型估计 baseline ← 又一次推理 # 5. PPO 算法更新策略和价值模型 # 一个 70B 的模型 × 4 份 ≈ 需要同时放 280B 参数在 GPU 上 # 这不仅费钱，而且超参数极其敏感——学习率、KL 系数、PPO clip 范围 # 哪个设错了都可能训崩

简单说：RLHF 又贵又脆弱。有没有办法绕开这些复杂性，但达到同样的效果？

5.2 DPO 的核心想法：跳过中间人

2023 年，斯坦福大学的研究者提出了 DPO（Direct Preference Optimization，直接偏好优化）。它的核心洞见可以用一句话概括：

DPO 的关键洞见

我们根本不需要单独训练一个奖励模型——
语言模型本身就可以当奖励模型用！

DPO 论文证明了：RLHF 的最优解等价于一个简单的监督学习问题。
不需要强化学习，不需要奖励模型，直接拿偏好数据训就行。

用类比来理解 RLHF 和 DPO 的区别：

RLHF 的做法

就像学做菜：
① 先请一个美食评委（奖励模型）
② 然后你不断做菜给评委品尝
③ 评委说"这道好 / 这道差"
④ 你根据评委的反馈改进

问题：培训一个靠谱的评委本身就很难

DPO 的做法

更聪明的学做菜：
① 直接给你看两道菜的对比照片
② 告诉你"左边这道更好"
③ 你自己分析左边好在哪里
④ 直接学习"好菜"的特点

优势：跳过了"培训评委"这一步

5.3 DPO 的损失函数：一行公式的直觉拆解

DPO 的损失函数看起来有点长，但拆开来看每一部分都有清晰的含义。别被符号吓到——我们一步一步来。

先看完整公式：

loss = -log( sigmoid( β × ( Δ好 - Δ差 ) ) ) 其中: Δ好 = log( π(好回答) / π_ref(好回答) ) Δ差 = log( π(差回答) / π_ref(差回答) ) π = 当前正在训练的模型 π_ref = 参考模型（SFT 模型，固定不变） β = 控制"多激进"的温度参数

现在逐层拆解：

第一层：π(回答) / π_ref(回答) —— "相对概率"

π(好回答) 是当前模型生成"好回答"的概率。
π_ref(好回答) 是 SFT 模型生成"好回答"的概率。

π / π_ref 就是"当前模型比 SFT 模型更倾向于生成这个回答的程度"。
比值 > 1 → 当前模型更喜欢这个回答（概率比 SFT 高了）
比值 < 1 → 当前模型不太喜欢这个回答（概率比 SFT 低了）
比值 = 1 → 和 SFT 一样，没有偏好变化

为什么要和 SFT 模型比，而不直接看绝对概率？因为这起到了 KL 惩罚的作用——和 RLHF 中的 KL 散度异曲同工。如果模型只提高了好回答的绝对概率，可能是通过"变得更极端"来实现的；但如果看的是相对变化，就要求模型在保持整体行为不崩的前提下，有针对性地调整偏好。

第二层：Δ好 - Δ差 —— "好坏之间的偏好差距"

Δ好 = 模型对"好回答"的倾向性变化
Δ差 = 模型对"差回答"的倾向性变化

Δ好 - Δ差 就是"模型是否在拉大好坏之间的差距"。

这个差 > 0 → 模型相比 SFT，更偏好好回答了。损失会变小。
这个差 < 0 → 模型反而更偏好差回答了。损失会变大！
这个差 = 0 → 模型的偏好没有改变。还需要继续学。

第三层：-log(sigmoid(...)) —— 把差距变成损失

这一层的作用和第二课学的交叉熵损失完全一样——把"好坏差距"转换为一个损失值：差距越大损失越小，差距越小（或反向）损失越大。

# 用具体数字感受一下： # 情况 1：模型学得很好 Δ好 = +2.0 ← 模型大幅提高了好回答的概率 Δ差 = -1.0 ← 模型降低了差回答的概率 差距 = 2.0 - (-1.0) = 3.0 ← 差距很大 loss = -log(sigmoid(3.0)) = 0.05 ← 损失很小 ✓ # 情况 2：模型还没学 Δ好 = +0.1 Δ差 = +0.05 差距 = 0.1 - 0.05 = 0.05 ← 差距很小 loss = -log(sigmoid(0.05)) = 0.67 ← 损失较大，需要继续学 # 情况 3：模型学反了！ Δ好 = -0.5 ← 好回答的概率反而降低了 Δ差 = +1.0 ← 差回答的概率反而提高了 差距 = -0.5 - 1.0 = -1.5 ← 方向完全错了 loss = -log(sigmoid(-1.5)) = 1.74 ← 损失很大！重罚 ✗
💡

一句话总结 DPO 在做什么：让模型看一对"好回答"和"差回答"，然后调整参数，使得模型相比起点（SFT）更倾向于生成好回答、更不倾向于生成差回答。如果做到了，损失变小；做反了，损失变大。就这样。

5.4 β 参数：控制"学习的激进程度"

公式里的 β（beta）控制模型对偏好信号的敏感度。直觉上：

# β 的作用： β 很大（如 0.5）→ 模型对偏好差距非常敏感 → 稍微的偏好差异就会被放大 → 学得快，但容易过拟合（"矫枉过正"） → 类似考试改卷时"扣分很严" β 很小（如 0.05）→ 模型对偏好差距不太敏感 → 需要很大的偏好差距才会产生显著的梯度 → 学得慢，但更稳健 → 类似改卷时"扣分很松" # 常用值：0.1 ~ 0.5 # 实践中通常从 0.1 开始调

5.5 DPO vs RLHF：全面对比

RLHF (PPO)

• 需要单独训练奖励模型
• 训练时要在线生成回答（慢）
• 同时跑 4 个模型（费显存）
• 超参数敏感，容易训崩
• 理论上上限更高（可持续探索）
• 需要强化学习知识

DPO

• ❌ 不需要奖励模型
• ❌ 不需要在线生成回答
• 只需 2 个模型（省一半显存）
• 稳定，像普通监督学习一样好调
• 实际效果和 RLHF 接近或持平
• 只需要会写 loss 就行

用代码对比一下训练流程的复杂度差异：

# RLHF 训练一步（伪代码，感受复杂度）： answer = policy_model.generate(question) # 在线生成（慢！） reward = reward_model.score(question, answer) # 奖励模型打分 ref_logp = ref_model.log_prob(question, answer) # 参考模型算概率 kl_penalty = policy_logp - ref_logp # 计算 KL 惩罚 value = value_model.estimate(question, answer) # 价值模型估计 advantage = reward - kl_penalty - value # 计算优势函数 ppo_update(policy_model, advantage, clip=0.2) # PPO 更新 value_model.update(...) # 更新价值模型 # —————————————————————————————— # DPO 训练一步（感受简单度）： logp_good = model.log_prob(question, good_answer) logp_bad = model.log_prob(question, bad_answer) ref_logp_good = ref_model.log_prob(question, good_answer) # 可预计算 ref_logp_bad = ref_model.log_prob(question, bad_answer) loss = -log(sigmoid(β * ( (logp_good - ref_logp_good) - (logp_bad - ref_logp_bad) ))) loss.backward() # 标准反向传播，就这么简单

5.6 DPO 之后：重要变体

DPO 的成功催生了一系列改进方法：

🔹 IPO（Identity Preference Optimization）

DPO 有一个理论问题：当偏好数据中好坏差距很大时，梯度会变得很小（sigmoid 饱和），模型可能学不到东西。IPO 用一个更简单的平方损失替代了 log-sigmoid，避免了梯度消失。

🔹 KTO（Kahneman-Tversky Optimization）

DPO 需要"成对"的偏好数据（同一个问题的好坏两个回答）。KTO 灵感来自行为经济学中的"前景理论"——人类对损失比收益更敏感。它只需要知道一个回答是"好的"还是"差的"，不需要成对比较。数据需求更宽松。

🔹 ORPO（Odds Ratio Preference Optimization）

更进一步简化：连参考模型都不需要了。它把 SFT 和偏好对齐合并为一步训练，减少了一次完整的训练阶段。

🎯

DPO 的实际影响：由于简单性，DPO 已经成为开源模型对齐的首选方法。LLaMA-3、Qwen-2、DeepSeek、Mistral 等都在使用 DPO 或其变体。它把"对齐"从一个复杂的强化学习工程问题简化为一个标准的监督学习问题——任何会写 PyTorch loss 的工程师都可以做对齐，大幅降低了门槛。

🧭

RLHF 还有用吗？有。虽然 DPO 更简单，但 RLHF 在某些场景仍有优势：① 当需要模型在线探索新的回答策略（而不只是在已有数据中选择）时，RLHF 更好；② 对于超大规模模型的精细对齐（如 GPT-4、Claude），OpenAI 和 Anthropic 仍然在使用 RLHF 或其变种。实际工业界中，DPO 和 RLHF 经常混合使用——先用 DPO 做粗调，再用 RLHF 精修。

把所有步骤串起来，这是一个大模型从出生到"上岗"的完整流程：

🏗️ 大模型的一生

7 HHH：对齐的三个目标

Anthropic（Claude 的母公司）提出了对齐的三个核心目标，被称为 HHH 原则：

HHH — 有用、无害、诚实

🟢 Helpful（有用）——模型应该尽最大努力帮助用户完成任务。如果用户问编程问题，给出能用的代码；如果用户写论文，给出有洞察力的建议。

🔴 Harmless（无害）——模型不应该帮助用户做坏事，不输出有害、有偏见或危险的内容。当检测到有害意图时应该拒绝。

🔵 Honest（诚实）——模型应该说实话，不确定时承认不确定，不编造信息。不应该为了讨好用户而顺着用户的错误观点说。

这三个目标之间有时会冲突：为了"无害"拒绝太多请求会降低"有用"；为了"有用"什么都回答会损害"无害"。对齐的艺术在于找到平衡。

一些经典的对齐难题：

  • "帮我写一个网络扫描工具" —— 安全研究者需要 vs 黑客也需要
  • "地球是平的对吗" —— 诚实地纠正 vs 用户可能被冒犯
  • "帮我写遗书" —— 可能是文学创作 vs 可能是真正的危机
  • "哪个候选人更好" —— 有用地分析 vs 保持中立不偏袒
🤔

对齐是一个开放问题："对齐"本质上是让 AI 的行为符合人类的价值观——但"人类的价值观"本身就不统一。不同文化、不同场景对"好回答"的定义不同。目前的对齐方法（RLHF/DPO）本质上是在学习标注者群体的平均偏好，它并不能真正"理解"道德。这是 AI 安全研究最前沿的课题之一。

8 前沿：对齐技术的最新发展

对齐领域仍在快速发展。以下是几个重要的新趋势：

🔹 Constitutional AI（宪法 AI）

Anthropic 提出的方法：不完全依赖人类标注，而是给模型一套"原则"（宪法），让模型自己判断什么是好回答。用 AI 来辅助 AI 对齐，降低对人类标注的依赖。

🔹 RLAIF（AI 反馈的强化学习）

用另一个强大的 AI 模型（而不是人类）来提供偏好反馈。规模化更容易，但需要确保"评委 AI"本身的偏好是好的。

🔹 Process Reward（过程奖励）

不只对最终答案打分，而是对推理过程的每一步打分。这让模型学会"正确的推理方式"而不只是"凑出正确答案"。对数学、编程等需要逐步推理的任务特别有效。

🔹 多轮对齐

传统 RLHF 主要关注单轮问答，但真实对话是多轮的。新的研究关注如何让模型在长对话中保持一致性、记住上下文、不被用户"绕晕"。

🚀

对齐 ≠ 限制：很多人误以为对齐就是给模型加限制、让它变笨。实际上好的对齐同时也让模型变得更有用——一个知道自己在和人对话（而不是在续写小说）的模型，能给出更精准、更有帮助的回答。对齐不是"给马套缰绳"，更像是"教孩子懂礼貌"——懂礼貌的孩子比不懂的更受欢迎、也能获得更多帮助。

9 检验你的理解

Q1: SFT（监督微调）的主要作用是什么？

✅ 正确！SFT 的核心作用是"格式转换"——把一个"文本续写器"变成一个"对话回答者"。知识在预训练中已经学到了，SFT 只是教模型如何把知识用"回答问题"的方式表达出来。
❌ SFT 的数据量很小（几千条），不足以学新知识。它的核心价值是教模型"对话的方式"——看到问题就回答，而不是续写更多文本。

Q2: RLHF 中的"奖励模型"是用什么数据训练的？

✅ 正确！人的相对判断（"A比B好"）比绝对判断（"A是7分"）更一致、更可靠。奖励模型的训练数据就是大量的偏好对：同一个问题的两个回答 + 人类的选择。模型学会了把"人更喜欢的"给高分。
❌ 绝对分数太主观、不稳定。RLHF 使用的是相对偏好——让标注者在两个回答中选择更好的那个。这种相对判断更一致，标注者之间的一致率通常比打分高得多。

Q3: DPO 相比 RLHF(PPO) 最大的优势是什么？

✅ 正确！DPO 把 RLHF 的多步流程（训练奖励模型→在线采样→PPO更新）压缩成一步监督学习。不需要维护奖励模型，不需要在线生成，训练更稳定、代码更简单。它仍然需要人类偏好数据，只是使用方式更直接。
❌ DPO 仍然需要人类偏好数据（和 RLHF 一样的格式）。它的优势在于简化了训练流程——跳过了奖励模型，直接从偏好数据到模型更新，一步到位。

Q4: RLHF 中的 KL 散度惩罚的作用是什么？

✅ 正确！没有 KL 约束，模型可能找到奖励模型的"漏洞"——生成一些实际很差但恰好能骗到高分的回答。KL 惩罚确保模型不会离 SFT 模型太远，保持回答的多样性和自然性。就像给学生说"创新可以，但不要走火入魔"。
❌ KL 惩罚限制模型的行为不要偏离参考模型太远。没有它，模型会"reward hacking"——找到奖励模型的漏洞并利用，生成不自然但高分的回答。
