第一课 · 预训练基础

Tokenization
文字如何变成数字

大模型看不懂文字，只能处理数字。Tokenization 就是把人类的语言翻译成机器能理解的「密码」的过程。

1 为什么需要 Tokenization？

在我们开始之前，先建立一个最基本的认知：计算机的本质就是数学运算器。无论多么"智能"的大模型，在底层执行的都是矩阵乘法、加法这些纯数学操作。它完全不认识"你""好""吗"这些符号——它只认识数字。

所以问题来了：我们和大模型交流的媒介是文字，而它只能处理数字。中间就需要一个"翻译官"，把文字转换成数字——这个翻译官就是 Tokenizer，它做的事情就叫 Tokenization。

一个类比故事

想象你是一个外星人，刚来到地球。你的大脑只能处理数字，完全不认识任何文字。

有人递给你一张纸条写着：「今天天气真好」

你需要先把它转换成数字才能理解。但是怎么切分呢？是一个字一个数字，还是一个词一个数字？切分的颗粒度不同，效果截然不同：

方案 A（按字符切）：每个字一个编号 →「今=42, 天=87, 天=87, 气=103, 真=256, 好=31」
→ 颗粒度最细，什么字都能表示，但序列很长，而且「天」字本身不携带"天气"还是"天空"的语义

方案 B（按词切）：每个词一个编号 →「今天=1024, 天气=2048, 真好=512」
→ 语义信息最丰富，但需要提前知道所有的词，遇到新词（如品牌名"特斯拉"）就傻了

方案 C（BPE，折中方案）：高频组合单独编号，其余拆开 →「今天=1024, 天气=2048, 真=256, 好=31」
→ 常见词完整保留，罕见词拆成更小的片段，既高效又灵活

大模型选择的就是 方案 C —— 一种介于字和词之间的「子词」(subword) 方案。这不是拍脑袋决定的，而是在实践中被反复验证为最佳平衡点的结果。

💡

核心直觉：Tokenization 是大模型的「感官系统」。就像我们的眼睛把光信号转为神经电信号，Tokenization 把文字转为数字序列（token IDs）。这一步决定了模型"看到"的世界长什么样——模型永远不会直接看到"你好"两个字，它看到的是类似 [35962, 12050] 这样的数字。

2 三种 Tokenization 方案的深度对比

在继续之前，先解释两个关键术语：

词表（Vocabulary）：Tokenizer 能认识的所有 token 的集合。你可以把它想象成一本"字典"——词表里有的词才能被识别，词表外的就是"生词"。词表越大，认识的词越多，但模型也越"胖"（参数更多）。

序列长度（Sequence Length）：一段文本被切分后的 token 数量。序列越长，模型处理起来越慢、越费算力。大模型通常有一个上下文窗口限制（比如 4096 或 128K tokens），所以把同样的内容用更少的 token 表示出来非常重要。

选择 Tokenization 方案的核心矛盾就是：词表大小 vs 序列长度的平衡。词表小 → 序列长；词表大 → 序列短但存储和计算开销大。来看三种典型方案：

字符级 (Character)

词表小但序列太长

每个字符一个 token。英文只需要 ~256 个 token（ASCII），中文需要几千个（常用汉字）。词表非常小，但文本被碎片化严重——一个常见的英文单词 "the" 要占 3 个 token 位，导致模型需要更多计算来"拼凑"语义。

"Hello" → ["H","e","l","l","o"] 5 个 tokens（词表仅需 ~256 个条目） 问题：序列太长，模型要花大量算力 来学习 "H+e+l+l+o = 打招呼" 这件事

词级 (Word)

直觉但词表爆炸

每个单词一个 token，最自然也最紧凑。但英文有几十万个词（加上人名、品牌、术语），词表膨胀到不可接受。更致命的是：遇到训练时没见过的新词就彻底不认识——这叫 OOV（Out of Vocabulary）问题。

"I love AI" → ["I","love","AI"] 仅 3 个 tokens，非常紧凑 ✓ "ChatGPT" → [UNK] ❌ 新造词完全无法处理，这在真实世界 中是不可接受的

子词级 (Subword / BPE)

当前主流方案 ✓

核心策略：常见词完整保留，罕见词拆成更小的有意义片段。词表大小通常在 3~10 万之间——比字符级大得多但远小于词级。由于高频词不需要拆分，序列长度也在合理范围内。

"ChatGPT" → ["Chat","G","PT"] 新词？没关系，拆开就认识了 ✓ "unhappiness" → ["un","happiness"] 子词本身也有语义："un" = 否定前缀 ✓ GPT-4 词表: ~100K tokens LLaMA 词表: ~32K tokens
⚖️

为什么 BPE 胜出？它巧妙地在三个维度取得了平衡：① 词表不太大（几万个），模型参数量可控；② 序列不太长，高频词作为整体保留；③ 永远不会遇到"不认识"的词——最坏情况下也能回退到字符级。这就是为什么 GPT、Claude、LLaMA 等主流大模型全都使用 BPE 或其变体。

3 BPE 算法：一步步看合并过程

知道了 BPE 是最好的方案之后，你一定好奇：它具体是怎么决定哪些字符组合应该成为一个 token 的？

BPE（Byte Pair Encoding，字节对编码）的算法思想优雅而简单，只有一条规则：反复找到当前出现频率最高的相邻 token 对，把它们合并成一个新 token。就这样不断重复，直到词表达到预设大小。

打个比方：就像一个刚开始学写字的小孩——

一开始只认识笔画（单个字符）→ 发现"氵"和"口"经常一起出现 → 学会了"活"的左半边
→ 又发现"氵"和"工"也常一起 → 学会了"江"的左半边
→ 随着见的文章越多，常用的字、词自然被"学会"了，罕见的字则保持拆分状态

下面的动画演示了 BPE 在一段简单英文语料上的训练过程。点击"下一步"，观察每一轮合并了哪个 pair、为什么选它（因为它出现频率最高），以及词表是如何一步步从单个字符成长为有意义的子词的：

训练语料："low low low low low lower lower newest newest newest widest"

看完这个过程，注意几个关键点：

1. 合并顺序就是"优先级"：先合并的 pair 说明在语料中更常见。在之后对新文本做 tokenize 时，也会按照同样的优先级顺序来应用这些规则。

2. 词表在"生长"：初始只有单个字符（比如 26 个字母），每合并一次，词表就多一个新 token。合并次数就是词表增长量——如果初始字符有 256 个，做 50000 次合并，最终词表就有约 50256 个 token（正好是 GPT-2 的词表大小）。

3. 训练完就固定了：BPE 的"训练"只需要一段足够大的文本语料，跑完合并后得到一份"合并规则表"。之后无论是预训练模型还是你跟 ChatGPT 聊天，用的都是这同一份规则。

4 Tokenization 在整个训练流程中的位置

现在你已经理解了 Tokenization 的原理。接下来我们把视角拉远，看看它在大模型训练这条"流水线"中处于什么位置，以及它和后续步骤之间的关系：

逐步来看这条流水线做了什么：

① 原始文本 → Tokenization：把人类的文字按照 BPE 规则切分成 token 序列。比如"我喜欢学AI" → ["我", "喜欢", "学", "A", "I"]。

② Tokenization → Token IDs：每个 token 在词表中有一个固定的编号（整数）。这一步纯粹是查表操作："我"→ 6423, "喜欢"→ 8821, "学"→ 3290…… 到这里，文字已经完全变成了一串数字。

③ Token IDs → Embedding：但光是一个整数编号太"粗糙"了。Embedding 层会把每个 ID 映射成一个高维向量（比如 768 维或 4096 维的浮点数数组）。这个向量才是模型真正"理解"语义的载体——语义相近的词，向量也会相近。这是下一课的重点。

④ Embedding → Transformer → 预测下一个 Token：向量进入 Transformer 神经网络，经过多层的注意力计算后，输出"下一个最可能的 token 是什么"。这就是大模型的核心训练任务，后续课程会详细讲。

🔑

关键认知：Tokenizer 在模型预训练之前就独立训练好了——它不是神经网络，不需要 GPU，只是一个统计算法。训练好后在整个模型的生命周期内保持不变。这也意味着：Tokenizer 的好坏直接影响模型能力的上限。如果 Tokenizer 把中文全拆成单字符，模型就需要用更多的"脑力"来重新拼凑语义，效率会大大降低。

✦ 真实世界里的 Tokenizer

在动手练习之前，让我们快速补充一些真实大模型中 Tokenizer 的有趣事实，帮你把课堂知识和实际产品连接起来：

你可能好奇的事

为什么 ChatGPT 有时候数不清字数？
因为它看到的不是"字"而是 token。"strawberry" 会被拆分为 ["st", "raw", "berry"] 之类的子词，模型并不知道这个词有几个字母 r——它从来没有在"字母"层面看过这个词。这是 Tokenization 设计带来的固有盲区。

为什么 GPT 处理中文比英文"贵"？
GPT 系列的 Tokenizer 主要在英文语料上训练，所以英文单词往往是完整的一个 token（如 "hello" = 1 token），而一个中文汉字可能需要 2-3 个 token。同样一句话，中文版消耗的 token 数远多于英文版，所以按 token 计费时中文更贵。这也是为什么 LLaMA、Qwen 等模型会专门扩充中文词表。

词表大小怎么选？
这是一个工程权衡。词表越大 → 每个 token 携带信息越多，序列越短，推理越快；但 Embedding 层参数更多，训练更慢。GPT-2 用 50K，GPT-4 用 ~100K，LLaMA 3 用 128K，DeepSeek 用 100K。总体趋势是越来越大，因为算力在增长，而更大词表带来的序列缩短收益很明显。

6 检验你的理解

回答下面的问题来检验你对本课内容的理解。如果没有信心，回头翻翻前面对应的章节再试。

Q1: 为什么大模型不用"词级"Tokenization？

✅ 正确！词级分词的词表可能有几十万甚至上百万个词，而且无法处理拼写变体、新造词等。BPE 用约 3~10 万的子词词表就能覆盖几乎所有文本。
❌ 再想想。提示：想想当用户输入一个从未见过的新词（比如品牌名）时，词级分词会怎样？

Q2: BPE 合并的顺序取决于什么？

✅ 正确！BPE 每一步都统计所有相邻 token 对的频率，把最高频的一对合并成新 token。这就是为什么常见词（如 "the"）会作为整体保留。
❌ 不对。提示：BPE 的核心是"统计"，它会数每一对相邻字符出现了多少次。

Q3: Tokenizer 是在什么时候训练的？

✅ 正确！Tokenizer 是独立训练的，它不是神经网络。训练好后，在预训练和推理阶段都保持不变。这也是为什么 GPT-4 和 GPT-3.5 可能使用不同的 Tokenizer。
❌ 不对。提示：Tokenizer 不是神经网络，它是用统计方法在语料上训练的独立组件。

7 编程练习：用代码巩固理解

看动画和读文字只能让你"觉得懂了"，真正的理解需要自己写一遍。接下来的编程练习会让你从零实现一个迷你版的 BPE Tokenizer——和真实大模型用的原理完全一样，只是规模小了 1000 倍。

这个练习把 BPE 拆成了 4 个小步骤，每完成一步都可以独立运行测试。即使你 Python 不太熟，每个任务也只需要写 5-10 行代码，而且有详细的注释提示。

🛠️ 你的任务：手写一个简易 BPE Tokenizer

在配套的 exercise.py 中，你需要按顺序完成以下 4 个任务：

任务 1：count_pairs() — 给一个 token 列表，统计所有相邻 pair 出现了多少次。
这是 BPE 的"眼睛"——它需要先看清楚哪些组合出现得最多，才能决定合并哪一对。

任务 2：merge_pair() — 给一个 token 列表和一个要合并的 pair，执行合并操作。
这是 BPE 的"手"——找到最高频 pair 后，就要在列表中把所有出现该 pair 的地方合并起来。

任务 3：train_bpe() — 把前两步组合起来，实现完整的 BPE 训练循环。
反复执行"统计 → 找最高频 → 合并"，这就是 BPE 训练的全部逻辑。你会发现，看似复杂的算法只需要一个简单的循环。

任务 4：encode() — 用训练好的合并规则对新文本进行编码。
训练是在语料上做的，但 encode 是对任何新文本使用。区分"训练"和"推理"是理解大模型的重要思维方式。
