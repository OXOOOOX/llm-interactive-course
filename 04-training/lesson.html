训练
模型如何从数据中学习

前三课我们搞清了模型的"身体结构"——Tokenization、Embedding、Transformer。但一个随机初始化的模型和一个训练好的模型，区别就像白纸和百科全书。这节课，我们揭开训练的全过程：模型如何从"什么都不懂"变成"能写诗能编程"。

本课的核心问题是：模型的几十亿甚至几千亿参数，是怎么被"调"到正确值的？

1 训练的本质：一个巨大的优化问题

大模型训练的逻辑极其简单，三句话就能说清：

训练三步走

① 前向传播：把一段文本喂给模型，让它预测下一个 token

② 计算损失：把模型的预测和真实答案做对比，算出"错得有多离谱"（Loss）

③ 反向传播 + 参数更新：根据"错误信号"，微调每个参数，让下次预测更准

然后重复以上三步，几十万次、几百万次……直到 Loss 足够低。

这就像一个学生做作业：做题（前向）→ 对答案（算损失）→ 分析错因并纠正（反向更新）→ 做下一题……循环往复，越来越好。

💡

关键直觉：训练不是"编程"——没有人告诉模型"遇到问号就回答问题"或者"名词后面跟动词"。模型的所有能力都是从"预测下一个 token"这个单一目标中涌现出来的。为了更好地预测下一个词，模型被迫学会了语法、语义、逻辑、甚至世界知识。

2 损失函数：衡量"猜得有多差"

训练的第一步是量化模型的"错误程度"。这个量化工具就是 损失函数（Loss Function）。对于语言模型，使用的是 交叉熵损失（Cross-Entropy Loss）。

假设词表有 50,000 个 token，模型对下一个 token 输出了一个 50,000 维的概率分布。而真实答案是某一个特定的 token（比如 ID=1234 的 "猫"）。

# 交叉熵损失的计算： # 模型输出的概率分布（经过 Softmax 后）： probs = [0.001, 0.002, ..., 0.15, ..., 0.003] # 50000 个值 # ↑ # token "猫" 的位置 # 真实答案：token "猫" 的 ID = 1234 target = 1234 # 交叉熵损失 = -log(模型给正确答案的概率) loss = -log(probs[target]) loss = -log(0.15) = 1.897 # 如果模型对正确答案给了很高的概率（如 0.95）： loss = -log(0.95) = 0.051 # 损失很低 ✓ 预测很好 # 如果模型对正确答案给了极低的概率（如 0.001）： loss = -log(0.001) = 6.908 # 损失很高 ✗ 预测很差

直觉解读：

  • Loss = 0：完美预测（给正确答案 100% 概率）—— 不可能达到，自然语言有内在的不确定性
  • Loss ≈ 1-2：很好的预测（正确答案在 Top-3 以内）
  • Loss ≈ 10+：几乎是瞎猜（随机初始化时的水平：-log(1/50000) ≈ 10.8）
📊

为什么用 -log？因为 log 有一个完美的特性：当概率接近 1 时，-log 接近 0（好的预测惩罚小）；当概率接近 0 时，-log 趋向无穷大（坏的预测惩罚极大）。这让模型受到强烈的激励去给正确答案分配高概率。同时 log 的导数形式简洁，便于计算梯度。

📉 -log(x) 曲线：直观感受损失函数

横轴是模型给正确答案的概率 p（0 到 1），纵轴是损失值 -log(p)。鼠标移上去查看任意点的值。注意曲线左陡右平的特征——猜得越离谱，惩罚增长越猛烈。

对于一整段文本，总损失是每个位置损失的平均：

# 训练文本："今天天气真好"（5 个 token） # 每个位置都要预测下一个 token： position 0: 输入 "今" → 预测 "天" → loss₀ = -log(p("天")) position 1: 输入 "今天" → 预测 "天" → loss₁ = -log(p("天")) position 2: 输入 "今天天" → 预测 "气" → loss₂ = -log(p("气")) position 3: 输入 "今天天气" → 预测 "真" → loss₃ = -log(p("真")) position 4: 输入 "今天天气真" → 预测 "好" → loss₄ = -log(p("好")) # 总损失 = 所有位置损失的平均 total_loss = (loss₀ + loss₁ + loss₂ + loss₃ + loss₄) / 5

3 梯度下降：朝"更好"的方向走一步

有了 Loss，我们知道模型现在有多差。但知道差不等于知道怎么改。模型有几十亿个参数，每个参数该往上调还是往下调、调多少？这就是 梯度下降（Gradient Descent） 要解决的问题。

核心思想：对每个参数，计算"如果这个参数增大一点点，Loss 会增大还是减小？"这个"变化率"就是 梯度（Gradient）。然后让参数朝着 Loss 减小的方向移动。

# 梯度下降的更新公式： 参数_new = 参数_old - learning_rate × 梯度 # 例：某个权重 w = 0.5，梯度 = 2.3 # learning_rate = 0.001 w_new = 0.5 - 0.001 × 2.3 = 0.4977 # 梯度为正 → 参数增大会增加 Loss → 所以减小参数 # 梯度为负 → 参数增大会减少 Loss → 所以增大参数 # 总之，参数总是朝着让 Loss 减小的方向移动

🏔️ 可视化：梯度下降找最低点

想象 Loss 是一个山谷的地形图，梯度下降就是小球从山坡上滚到最低点。点击按钮观察不同学习率的效果：

学习率（Learning Rate）是训练中最重要的超参数之一：

  • 太小：每步移动微小，训练极慢，可能困在局部最优
  • 太大：每步跨太远，在最优解附近反复震荡，甚至发散（Loss 越来越大）
  • 合适：快速收敛到最优解附近
🎓

类比：梯度下降就像在雾天下山——你看不到全貌，只能感受脚下的坡度（梯度），然后朝着"最陡下坡方向"迈一步。学习率就是你的步幅：步子太小会在山上走到天黑；步子太大会直接冲下悬崖或者在山谷两侧来回弹跳。

4 反向传播：高效计算所有梯度

一个大模型有几十亿个参数。如果对每个参数单独测试"增大一点点看 Loss 变多少"，那计算量是不可接受的。反向传播（Backpropagation）用一次巧妙的递推就能同时算出所有参数的梯度。

它的核心原理是微积分中的链式法则（Chain Rule）：

# 链式法则的直觉： # 假设 Loss 依赖于 A，A 依赖于 B，B 依赖于参数 w # Loss = f(A), A = g(B), B = h(w) # 那么 Loss 对 w 的梯度 = 各环节梯度的乘积： ∂Loss/∂w = (∂Loss/∂A) × (∂A/∂B) × (∂B/∂w) # 就像多米诺骨牌： # w 变了 → B 跟着变 → A 跟着变 → Loss 跟着变 # 每一环的"传导率"相乘 = 总的影响

反向传播的计算方向是从后往前（从 Loss 回推到每个参数）：

# 前向传播（从左到右）： Input → Embedding → Attention → FFN → ... → Softmax → Loss # 反向传播（从右到左）： Loss → ∂L/∂Softmax → ∂L/∂FFN → ∂L/∂Attention → ∂L/∂Embedding → ∂L/∂参数 # 每到一层就能算出该层所有参数的梯度 # 一次前向 + 一次反向 = 所有参数梯度全部算完
⚡

反向传播的精妙之处：假设有 1750 亿个参数（GPT-3）。如果用"逐个试探"的笨办法，需要做 1750 亿次前向传播来算梯度。但反向传播只需要一次前向 + 一次反向——约等于两次前向的计算量。这个算法把时间复杂度从 O(参数量 × 前向计算) 降到了 O(前向计算)，是深度学习能够成功的关键之一。

5 完整的训练循环

把前面的知识串起来，这是一个完整的训练步骤：

① 从训练数据中取一个 Batch（批次）
↓
② 前向传播：输入 → 模型 → 预测概率
↓
③ 计算 Loss（预测 vs 真实的差距）
↓
④ 反向传播：算出所有参数的梯度
↓
⑤ 更新参数：参数 -= 学习率 × 梯度
↺ 重复几百万次，直到 Loss 足够低
# 伪代码：训练循环 model = initialize_random_parameters() optimizer = Adam(lr=3e-4) for step in range(500_000): # 训练 50 万步 batch = get_random_batch(data) # 取一批训练数据 predictions = model.forward(batch) # 前向传播 loss = cross_entropy(predictions, targets) # 算损失 gradients = model.backward(loss) # 反向传播 optimizer.step(gradients) # 更新参数 if step % 1000 == 0: print(f"Step {step}, Loss: {loss:.4f}") # 监控进度

Batch（批次）的概念很重要：每一步不是只处理一个样本，而是同时处理一"批"样本（比如 2048 个序列），然后用这批样本的平均梯度来更新参数。这样做的好处是：

  • 单个样本的梯度可能有噪声——一批样本的平均梯度更稳定、方向更准
  • GPU 擅长并行计算——处理 1 个和处理 2048 个的时间差不多

6 训练数据：用什么来教模型？

训练大模型需要海量高质量文本数据。数据的质量和规模直接决定了模型的能力上限。

# 主流大模型的训练数据规模： GPT-3: 300B tokens (3000 亿) LLaMA-2: 2T tokens (2 万亿) LLaMA-3: 15T tokens (15 万亿) DeepSeek-V3: 14.8T tokens # 数据来源（典型构成）： 网页文本 (Common Crawl): ~60% # 互联网爬取 书籍: ~15% # 电子书、学术著作 代码 (GitHub): ~10% # 编程能力的来源 学术论文 (arXiv): ~5% # 科学知识 维基百科: ~3% # 结构化知识 其他 (论坛、问答、新闻): ~7%

数据质量比数量更重要：

  • 去重：互联网上大量文本是重复的，不去重模型会"背诵"而非"学习"
  • 过滤：去掉低质量内容（广告、乱码、生成式垃圾文本）
  • 配比：不同类型数据的比例影响模型的能力分布
📚

数据决定能力：模型只能学到训练数据中包含的知识。如果数据中没有某种语言、某个领域、或者某种推理模式——模型就不会那些能力。这就是为什么"数据工程"在大模型训练中地位如此重要，某种意义上比模型架构本身更重要。"Garbage in, garbage out"——数据差，模型再大也没用。

7 优化技巧：让训练更快更稳

简单的梯度下降在实际训练大模型时远远不够。几十年的研究产出了很多关键的优化技巧：

🔹 Adam 优化器

目前训练大模型最常用的优化器。它为每个参数维护了"动量"（过去梯度的移动平均）和"二阶矩"（梯度大小的移动平均），让参数更新更平滑、更自适应。

# Adam 的直觉： # 普通梯度下降：一步一步走，每步只看当前坡度 # Adam：像一个有惯性的小球滚下山 # - 有动量：不会因为一步的随机噪声就改变方向 # - 自适应：对"地形平坦"的维度步子大，"地形陡峭"的维度步子小 # 超参数（几乎所有大模型都用这套）： lr = 3e-4 # 峰值学习率（会随训练调整） beta1 = 0.9 # 动量衰减系数 beta2 = 0.999 # 二阶矩衰减系数 weight_decay = 0.1 # 权重衰减（防止过拟合）

🔹 学习率调度（Learning Rate Schedule）

学习率不是固定的，而是随训练过程动态变化：

# 典型的学习率变化曲线： # Warmup 阶段（前 1-2% 的步数）： # lr 从 0 线性增大到峰值 → 防止刚开始训练时梯度过大导致发散 # Cosine Decay 阶段（剩余步数）： # lr 按余弦曲线缓慢衰减到接近 0 → 让训练后期更精细地收敛 ╱‾‾‾╲ ╱ ╲ ╱ ╲ ╱ ╲ ╱ ╲ ──╱ ╲────── ↑ ↑ warmup cosine decay

🔹 梯度裁剪（Gradient Clipping）

如果某一步的梯度特别大（可能因为数据中的异常样本），直接更新可能让训练"炸掉"。梯度裁剪限制梯度的最大范数，就像给汽车装了限速器。

🔹 混合精度训练（Mixed Precision）

用较低精度的数字格式（FP16/BF16）做前向和反向计算，节省显存和计算量；但用全精度（FP32）存储参数和做更新，避免精度损失。训练速度提升约 2 倍，显存减半。

Scaling Law（缩放定律）：OpenAI 2020 年的研究发现了一个惊人的规律——模型的性能（Loss）和三个因素存在幂律关系：参数量 N、数据量 D、计算量 C。只要你持续增加这三者，模型性能就会平滑、可预测地提升。这就是大家疯狂"卷算力"的理论基础——目前为止还没有看到天花板。

9 检验你的理解

Q1: 交叉熵损失 loss = -log(p) 中，如果模型给正确答案的概率 p = 1，loss 等于多少？

✅ 正确！-log(1) = 0。当模型对正确答案的置信度为 100% 时，损失为零。但实际中几乎不可能达到——因为自然语言有内在的不确定性（同一个前文可以接多个合理的后续）。
❌ 回忆一下对数函数：log(1) = 0，所以 -log(1) = 0。当概率为 1 时损失为 0，概率越小损失越大。

Q2: 梯度下降中，如果某个参数的梯度为负数，这个参数应该怎么更新？

✅ 正确！w_new = w - lr × (-负值) = w + lr × 正值，所以参数增大。直觉：梯度为负说明"增大参数会让 Loss 减小"，所以我们确实应该增大它。更新公式中的减号和负梯度一抵消，就是往增大方向走。
❌ 代入公式想一想：w_new = w - lr × gradient。如果 gradient = -2，那 w_new = w - lr×(-2) = w + 2lr。结果是参数增大了。梯度为负 = "增大这个参数有利于减小 Loss"。

Q3: 反向传播的核心原理是什么？

✅ 正确！链式法则让我们可以把"Loss 对任意参数的梯度"分解为"各层之间的局部梯度"的乘积。从 Loss 出发，逐层向前传递梯度信号，每到一层就能算出该层所有参数的梯度。一次反向就搞定所有参数，复杂度仅为前向计算的约 2 倍。
❌ 逐个试探需要 N 次前向（N=参数数量），对大模型来说不可行。反向传播用链式法则，一次递推就能算出所有参数的梯度。

Q4: Batch Size（批大小）越大越好吗？

✅ 正确！更大的 Batch 确实给出更准的梯度估计，但也需要更多 GPU 显存。而且研究发现，适量的梯度噪声（来自小 Batch）反而有正则化效果，帮助模型泛化。实际中通常选择一个"够大但不过大"的 Batch Size，然后通过梯度累积来模拟更大的有效 Batch。
❌ Batch Size 的选择是一个 trade-off：更大→梯度更准、GPU 利用率更高；但也→显存占用大、可能过拟合。实际中需要平衡。
