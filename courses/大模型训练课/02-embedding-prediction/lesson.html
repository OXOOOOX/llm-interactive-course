本课分两大主题：Embedding——把编号变成有语义的向量；以及 Next-Token Prediction——大模型唯一的训练任务。理解了这两件事，你就掌握了预训练的核心逻辑。

1 为什么 Token ID 不够用？

上节课我们得到了一串 Token ID，比如 "我喜欢学AI" → [6423, 8821, 3290, 65, 40]。看起来已经是数字了，可以直接喂给模型了？

不行。这些 ID 只是字典里的"门牌号"——纯粹的编号，没有任何语义信息。

门牌号的问题

假设词表中："猫"的 ID 是 5，"狗"的 ID 是 6，"钢筋"的 ID 是 7。

从 ID 来看，|6 - 5| = 1，|7 - 6| = 1——"猫"和"狗"的距离，与"狗"和"钢筋"的距离完全一样。但我们知道"猫"和"狗"语义上远比"狗"和"钢筋"更相似——它们都是宠物、都是动物。

问题的本质：一个整数只有一个维度，它无法同时编码一个词的多种属性（是否是动物？是否是名词？情感倾向？使用频率？……）。我们需要一种更丰富的数字表示方式。

这就是 Embedding 要解决的问题：把一个整数 ID 展开成一个高维向量，让每个维度都能承载不同的语义信息。

2 Embedding：把编号展开成向量

Embedding 的操作其实非常简单——它就是一个巨大的查找表（lookup table）。

想象一本"超级字典"：每个 Token ID 对应一行，每行是一个包含几千个浮点数的向量。当模型收到一个 Token ID 时，就去查这本字典，取出对应的那一行向量。

# Embedding 查找表的核心操作 # 假设词表大小 = 50000，向量维度 = 768 embedding_table = 一个 50000 × 768 的矩阵 # 这就是模型要"学"的参数 token_id = 6423 # "我" 的 ID vector = embedding_table[6423] # 取出第 6423 行 → 得到一个 768 维向量 # 结果类似：[0.12, -0.34, 0.56, 0.01, ..., -0.23] （768 个浮点数）

几个关键点：

向量维度是一个重要的超参数。GPT-2 用 768 维，GPT-3 用 12288 维，GPT-4 据推测可能更大。维度越高，每个 token 能携带的信息越多，但计算量也越大。你可以把维度理解为"描述一个词需要多少个独立属性"。

初始值是随机的。在模型训练开始时，这个表里的数字是随机生成的——此时"猫"和"钢筋"的向量没有任何区别。但随着训练进行，模型会自动调整这些数字，让语义相近的词的向量也彼此接近。这个"自动调整"就是我们常说的"学习"。

Embedding Table 是怎么"长出来"的？

你可能会好奇：这个装满浮点数的巨大表格，数值到底是哪里来的？答案是——模型自己"学"出来的。整个过程分三个阶段：

阶段一：出生（随机初始化）
模型刚创建时，Embedding Table 里填满了随机数。此时"猫"的向量可能是 [0.42, -0.13, 0.87, ...]，"狗"的向量是 [-0.56, 0.71, 0.03, ...]——完全没有规律，和语义毫无关系。

阶段二：训练（在海量文本中反复调整）
在预训练过程中（第 4~6 节会详讲），模型不断做"预测下一个词"的练习。每次预测错误，反向传播算法就会微调所有参数——包括 Embedding Table 里的每一个数字。关键洞察是：因为"猫"和"狗"经常出现在相似的上下文里（"我养了一只___"、"它在沙发上睡觉"……），为了在这些上下文中都做出正确预测，优化过程会自然地让"猫"和"狗"的向量逐步靠近。

阶段三：成熟（形成有意义的语义空间）
经过在数万亿 token 上的训练后，Table 里的数值趋于稳定。此时语义相近的词在向量空间中自然聚在一起——这不是人类预先设计的，而是优化过程的自然产物。下一节我们会直观看到这种聚类效果。

Embedding 层的参数量不小。词表 50000 × 维度 768 = 约 3800 万个参数，这只是整个模型的一小部分，但它是模型"感知世界"的起点。

💡

类比理解向量维度：用 1 个数字只能描述"大小"。用 2 个数字可以描述"位置"（x, y）。用 3 个数字可以描述"空间位置"（x, y, z）。用 768 个数字呢？可以同时编码一个词的词性、情感倾向、正式程度、领域归属、时态、单复数……等等无数种特征。人类很难直观理解 768 维空间，但数学上它工作得很好。

3 语义空间：意思相近的词靠在一起

经过训练后，Embedding 空间会呈现一种神奇的特性：语义相似的词，在高维空间中彼此距离更近。

真实的 Embedding 是几千维的，我们无法直接看到。但如果把它"压扁"到 2 维平面上（一种叫 t-SNE 或 PCA 的降维技术），就能看到下面这样的分布——动物聚在一起，食物聚在一起，科技词汇聚在一起：

Embedding 空间二维投影（模拟）

下面每个圆点代表一个词的 Embedding 向量投影到二维平面的位置。鼠标悬停查看词和它的"邻居"。注意语义相关的词是如何自然聚类的。

更有趣的是，Embedding 空间中会出现有意义的方向。最经典的例子：

向量("国王") - 向量("男人") + 向量("女人") ≈ 向量("王后")

也就是说，"男人→女人"这个方向，和"国王→王后"这个方向，在高维空间中几乎是平行的。模型通过训练自己"发现"了性别这个抽象概念，并且用向量方向来编码它。

这不是人类设计的——没有人告诉模型"把性别编码在第 137 维上"。这是模型在大量文本中自动发现的统计规律：因为"国王"和"王后"总是出现在相似的上下文中（"坐在王座上""统治国家"……），只不过一个和"他"共现、一个和"她"共现，模型就学会了用向量方向来表达这种系统性差异。

⚡

为什么这很重要？Embedding 是大模型一切能力的基础。模型后续所有的"思考"（Transformer 层的计算）都在这个向量空间中进行。如果 Embedding 没有学好——比如"猫"和"狗"的向量相距甚远——那后面再多的 Transformer 层也难以弥补。可以说，Embedding 的质量决定了模型理解语义的下限。

✦ 延伸：什么是"Embedding 模型"？

你可能在各种地方听说过 OpenAI 的 text-embedding-3-small、开源的 BGE、BERT 等被称为"Embedding 模型"。它们和我们刚讲的 Embedding 层是什么关系？

Embedding 层是大语言模型（如 GPT）内部的一个组件——它只是整个模型的"第一步"，负责把 Token ID 转换成向量。向量送入 Transformer 后，最终目的是预测下一个 token。

Embedding 模型则是一个独立的、专门用来生成语义向量的模型。它通常是一个去掉了"预测头"的 Transformer——不负责预测下一个词，而是把输入的一整段文字"压缩"成一个固定长度的向量（比如 1536 维）。

# 大语言模型中的 Embedding 层（模型内部的一个步骤） "今天天气真好" → Token IDs → Embedding 层 → 向量序列 → Transformer → 预测下一个词 # 独立的 Embedding 模型（专门输出语义向量） "今天天气真好" → Token IDs → Transformer → 一个向量 [0.12, -0.34, ..., 0.56] ↑ 这个向量代表整句话的"语义坐标"

Embedding 模型的核心用途是把文本变成可以比较的数字。有了语义向量，计算机就能用数学方法衡量"两段文字有多像"——这正是以下应用的基础：

🔍

Embedding 模型的典型应用：
① 语义搜索：用户搜"怎么养猫"，即使文档里写的是"猫咪饲养指南"，通过向量相似度也能匹配到——因为两句话的 Embedding 向量非常接近。
② RAG（检索增强生成）：先用 Embedding 模型从知识库中找到与问题最相关的段落，再喂给大模型生成回答。这就是 ChatGPT 联网搜索和企业知识库问答的基本原理。
③ 文本分类与聚类：把大量文本转换成向量后，用传统机器学习方法进行自动归类——比如把客服工单自动分到"退款""物流""技术支持"等类别。

简单记住：大模型里的 Embedding 层是"内部零件"，Embedding 模型是"独立工具"。它们共享相同的核心思想——把文本映射到高维向量空间——但用途和使用方式不同。

4 Next-Token Prediction：大模型唯一的训练目标

现在来到预训练最核心的概念。如果你这节课只记住一件事，就记住这个：

大模型预训练的全部任务，就是一件事

给定前面的所有 token，预测下一个 token 最可能是什么。

就这么简单。没有其他目标、没有其他任务。GPT-3 的 1750 亿个参数、用了几百万美元的训练费用，全部用来学这一件事：猜下一个词。

具体来说，假设训练语料中有一句话"今天天气真好"。模型需要做以下预测：

# 模型看到的上下文 → 需要预测的下一个 token "今" → 天 # 给了"今"，猜下一个是"天" "今 天" → 天 # 给了"今天"，猜下一个是"天"（天气的天） "今 天 天" → 气 # 给了"今天天"，猜下一个是"气" "今 天 天 气" → 真 # 给了"今天天气"，猜下一个是"真" "今 天 天 气 真" → 好 # 给了"今天天气真"，猜下一个是"好"

注意：一句话会产生多个训练样本。每个位置都是一个独立的"猜下一个词"任务。这就是为什么大模型的训练效率很高——一句 100 个 token 的话可以产生 99 个训练样本。

你可能会问："就靠猜下一个词，怎么能学会翻译、写代码、做数学？"

这正是 Next-Token Prediction 最深刻的地方。为了准确预测下一个词，模型不得不理解非常多的东西：

为了预测 "巴黎是法国的___" → "首都"
→ 模型必须学会地理知识

为了预测 "if x > 0: return___" → 相关的代码逻辑
→ 模型必须学会编程语法和逻辑

为了预测 "2 + 3 = ___" → "5"
→ 模型必须学会基本算术

为了预测 "他非常难过，因为___" → 合理的原因
→ 模型必须学会因果推理和情感理解

换句话说：Next-Token Prediction 是一个"表面简单但内涵无限"的任务。它迫使模型在学习预测下一个词的过程中，顺便把人类知识的方方面面都内化了。这就是预训练的深刻之处。

🎯

一个精妙的设计：Next-Token Prediction 是一个自监督（Self-supervised）任务——训练数据不需要人工标注。任何一段文本天然就是训练数据：遮住最后一个词，前面的词就是输入，被遮住的就是标签。这意味着整个互联网的文本都可以拿来做训练数据，这是大模型能规模化的根本原因。

5 模型如何"猜"：概率分布与 Softmax

模型预测下一个 token 时，不是给出一个确定的答案，而是对词表中的每一个 token 给出一个概率。

比如给定"今天天气真"，模型可能输出这样的概率分布：

🎯 Next-Token Prediction 演示

今天天气真 ___?

模型对词表中每个 token 给出的概率（只展示 Top 8）：

词表中其余 ~50000 个 token 共享剩下的 ~2% 概率

这个概率分布是怎么算出来的？分两步：

第一步：Transformer 输出原始分数（logits）。模型的最后一层会为词表中每个 token 输出一个"分数"——可以是任意实数，正的负的都有。分数越高表示模型觉得这个 token 越可能是下一个。

第二步：Softmax 把分数变成概率。原始分数不能直接当概率用（可能是负数，也不一定加起来等于 1）。Softmax 函数的作用是：把任意一组实数转化为一组介于 0~1 之间、且加和为 1 的概率值。数学公式是：

# Softmax 公式（不用记住，理解直觉就够了） softmax(x_i) = e^(x_i) / Σ e^(x_j) # 直觉：先把每个分数"放大"（取指数 e^x）， # 然后除以总和，这样所有概率加起来正好等于 1。 # 分数越高的 token，概率指数级增大（赢家通吃效果）。 # 例如： logits = [5.2, 3.1, 1.0, -0.5] # 原始分数 softmax = [0.85, 0.10, 0.04, 0.01] # 转换后的概率（加和 = 1）
🔑

Softmax 的直觉：它像一个"民主投票放大器"。如果一个选项的分数比其他选项高很多，Softmax 会让它的概率遥遥领先（类似"赢家通吃"）。如果几个选项分数接近，概率也会比较平均（类似"难以抉择"）。这正好反映了语言的特点：有时下一个词几乎确定（"中华人民共和___"），有时有多种合理选择（"我喜欢吃___"）。

6 模型如何从"瞎猜"变成"精准预测"？

现在我们知道模型会输出一个概率分布。但在训练初期，由于参数是随机的，模型的预测几乎是瞎猜——比如把 2% 的概率给了正确答案"好"，35% 给了错误的"的"。模型怎么从"瞎猜"进化到"精准预测"的？

答案是一个不断重复的三步循环：

训练三步走

① 前向传播：把文本喂给模型，让它预测下一个 token，得到概率分布

② 计算损失：用交叉熵损失衡量"猜得有多差"——公式是 loss = -log(p)，p 是模型给正确答案的概率。p 越高损失越小，p 越低损失越大。

③ 反向传播 + 更新参数：根据损失信号，用梯度下降微调每个参数，让下次预测更准。核心公式：参数 = 参数 - 学习率 × 梯度

重复以上三步，几十万次、几百万次……模型就从"什么都不懂"变成了"能写诗能编程"。

你可能会好奇：梯度是什么？反向传播怎么工作？学习率怎么选？为什么用 -log 而不是别的函数？——这些问题我们会在第四课：训练中详细展开，包括互动演示和数学直觉。

现在你只需要记住这个核心直觉：

学习的本质：每一步的改进微乎其微——把某些参数调高 0.001，某些调低 0.0005。但千万步的微小改进累积起来，模型就从"对所有事情一无所知的随机噪声"变成了"能流利说话、写代码、做数学的强大模型"。量变引起质变。

7 把它们串起来：预训练的完整画面

现在让我们把本课学的所有概念串成一条完整的链路。预训练就是在不断地重复这个循环：

一次训练迭代的全过程

Step 1 — Tokenize：用 BPE Tokenizer 把文本切成 token 序列：["今天", "天气", "真", "好"]

Step 2 — 查 Embedding 表：每个 token ID 查出对应的向量，输入变成了一组高维向量。

Step 3 — Transformer 处理：向量送入 Transformer 网络（下节课详讲），输出每个位置的"预测向量"。

Step 4 — 预测 + 计算损失 + 更新参数：预测向量经过 Softmax 得到概率分布，与正确答案比对得到损失，再通过梯度下降微调参数。（第四课会详细讲解这一步）

Step 5 — 重复。换一批数据，重复上述过程。数百万次迭代后，模型从"瞎猜"变成"预训练完成的基座模型"。

🔑

本课核心要点总结：
① Embedding 把 Token ID 展开为高维向量，让模型能用"距离"来表达"语义相似性"
② 训练之后，Embedding 空间会自动形成有意义的聚类和方向
③ 预训练的唯一目标是 Next-Token Prediction——给定前文，猜下一个 token
④ 这个看似简单的任务迫使模型内化了语法、知识、推理等能力
⑤ 训练通过"计算损失 → 梯度下降 → 更新参数"的循环不断改进模型（第四课详讲）

8 检验你的理解

回答下面的问题来检验你对本课内容的掌握。

Q1: 为什么不能直接用 Token ID（整数）作为模型的输入？

✅ 正确！Token ID 只是字典中的门牌号。"猫"=5 和"狗"=6 的编号差距为 1，但"狗"=6 和"钢筋"=7 的差距也是 1——整数编号完全无法反映语义距离。Embedding 向量通过高维空间解决了这个问题。
❌ 整数当然可以参与运算，也不存在太大的问题。关键在于：一个整数只有一个维度，无法编码丰富的语义信息。

Q2: 大模型预训练的训练目标是什么？

✅ 正确！Next-Token Prediction 是预训练的唯一目标。"回答问题"和"判断情感"是后训练（SFT/RLHF）阶段才教给模型的。但正是因为预测下一个词需要深刻的语言理解，模型在这个过程中"顺便"学会了各种知识和推理能力。
❌ "回答问题"和"理解情感"都不是预训练阶段的目标。预训练只做一件事：预测下一个 token。回答问题是后训练（SFT）阶段的任务。

Q3: Embedding 表中的数值最初是怎么来的？

✅ 正确！Embedding 表一开始填满随机数，此时所有词的向量毫无意义。但在训练过程中（不断做 Next-Token Prediction），反向传播会自动调整这些数字，让语义相近的词逐渐在向量空间中聚到一起。
❌ Embedding 表不是人为设定的，也不来自字典。它从随机数开始，在训练过程中通过梯度下降自动学出有意义的语义向量。

Q4: 为什么 Next-Token Prediction 能让模型学会"知识"？

✅ 正确！要预测"巴黎是法国的___"后面是"首都"，模型必须在参数中"记住"巴黎是法国首都这个事实。知识不是显式存储的，而是隐含在模型参数中——参数的某种组合恰好编码了这条知识。
❌ 预训练数据不需要任何人工标注（这是自监督学习的优势）。模型也没有专门的"知识库"模块。知识是在预测下一个词的过程中隐式学到的。

9 编程练习：用代码模拟前向传播

这节课的编程练习会让你亲手实现从 Token ID 到概率预测的完整前向传播过程（Forward Pass）——这正是大模型每次"猜下一个词"时实际执行的计算链路。

我们会跳过复杂的 Transformer 部分（那是第三课的内容），用一个简化的线性层代替，但 Embedding 查找、Softmax、交叉熵损失这些核心计算你将完整实现。

🛠️ 你的任务

在配套的 exercise.py 中，按顺序完成 5 个任务：

任务 1：embedding_lookup() — 根据 Token ID 从 Embedding 矩阵中查出向量
最简单的一步：本质就是用 ID 当索引去矩阵里取一行。但这一步是所有后续计算的起点。

任务 2：cosine_similarity() — 计算两个向量的余弦相似度
这是衡量"两个词有多像"的标准方法。余弦相似度 = 1 表示方向完全一致，= 0 表示正交，= -1 表示方向相反。

任务 3：softmax() — 把一组原始分数转化为概率分布
模型输出的 logits 可以是任意实数，Softmax 让它们变成合法的概率（0~1 之间，总和为 1）。

任务 4：cross_entropy_loss() — 计算交叉熵损失
训练的"评分器"——衡量模型给正确答案的概率有多高。loss 越小说明预测越准。

任务 5：predict_next_token() — 串联前面的步骤，完成一次完整的前向传播
把 Embedding + 线性层 + Softmax 组合起来，模拟模型预测下一个 token 的完整过程。

📂 打开 exercise.py，搜索 TODO 找到需要填写的位置
▶️ 每完成一个任务就运行 python exercise.py 查看测试结果
🎉 全部 5 个测试通过 = 你已经理解了预训练的核心计算链路！
